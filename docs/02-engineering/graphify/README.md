# Graphify Research Surface

> 状态: Research / Reference
> 目标: 收口 Graphify 与团队知识基座相关的研究材料、对比分析和采用判断，作为 Crazy 后续是否引入 Graphify 的受追踪输入层。

## One-Page Summary

### 这个目录解决什么问题

- 保存与 Graphify 相关的外部方法论材料与内部对比分析
- 为 Crazy / FlowMind 是否采用 Graphify 提供统一研究入口
- 避免 Graphify 讨论只停留在群聊或阿里云临时文件中

### 谁应该读

- 需要评估是否把 Graphify 引入 Crazy / FlowMind 工作流的人
- 负责知识运营、MCP、研发效率平台或架构治理的人
- 需要理解“AI全栈研发知识基座”与 Graphify 差异的人

### 先读哪三份

1. [ai-fullstack-knowledge-base-article.md](./ai-fullstack-knowledge-base-article.md)
2. [ai-fullstack-kb-vs-graphify-comparison.md](./ai-fullstack-kb-vs-graphify-comparison.md)
3. [HARNESS-ENTRY.md](../harness/HARNESS-ENTRY.md)

### 典型工作流

1. 先读当前仓库的 harness / PRD / roadmap 事实层
2. 再用这里的材料判断 Graphify 是否适合作为 sidecar 知识层接入
3. 若决定采用，再把结论回写到仓库事实层而不是停留在研究层

### 常见误区

- 把研究材料直接当成已批准实施的方案
- 把 Graphify 当成 truth authority，而不是只读 sidecar
- 没有把研究结论回写到仓库文档，只在口头上说“可以采用”
