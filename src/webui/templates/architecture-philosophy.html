HermesAgent = 运行时宿主 FlowMind = 治理真相层 CrazyAgentsManage = 可操作的产品层

产品定位堆栈

把宿主、真相层、产品层和运营对象分开，避免叙事打架。

运行时宿主

HermesAgent

负责执行、接入平台、维持运行时状态、承载会话与工具链，是系统的操作发生地。

治理真相层

FlowMind

负责定义规范、沉淀母文档、接住 candidate 到 canonical truth 的提升过程，是产品不漂移的约束层。

产品层

CrazyAgentsManage

负责把运行态做成用户能读、运营能管、治理能追责的表面，而不是再造一个“Agent 游乐场”。

运营对象

Session / Skill / Memory / Handoff / Truth

这些是产品真正经营的对象。页面、图谱和仪表板都只是它们的呈现方式。

六条产品原则

直接来自当前母 PRD 的约束，不展开到底层 API 设计。

运行态先可读

先让操作者看清现在发生了什么，再谈更多编排能力。

运营对象先可管

技能、告警、记忆、会话、定时任务都要能被操作，而不只是能被列出来。

治理闭环必须显式

什么是 candidate，什么是 canonical truth，什么还在 review，不能混在一起。

事实优先于聊天记录

群聊和会话不是持久真相，仓库文档、harness 记录与 closeout 证据才是。

Hermes 与 FlowMind 分工清晰

Hermes 负责运行与运营动作，FlowMind 负责规范和治理提升，产品层承接两者。

页面必须连接实施动态

架构页不是静态 PPT，必须能回到真实路由、真实状态和真实证据。

从意图到仓库事实的产品闭环

产品哲学不是口号，它必须落到实际流转链路上。

输入侧

用户 / 平台事件

来自 CLI、Feishu、Webhook、Cron、API Server 的意图进入 Hermes 运行面。

执行侧

HermesAgent 运行

生成会话、调用工具、更新状态文件与数据库，构成一切运营对象的原始现场。

产品表面

CrazyAgentsManage

把运行态抽成 Overview / Runtime / Operations / Governance / Collaboration 五大责任面。

规范侧

FlowMind 治理真相

把设计稿、PRD、路线图、closeout 结论提升为可复用的规范性事实。

协作侧

Codex ↔ HermesAgent

通过 handoff packet、runtime snapshot、harness 记录协作，不让结论只留在聊天里。

沉淀侧

Repo Facts / Harness

最终形成仓库中的持久事实，反过来约束下一轮实施和运营判断。

边界裁定

这是以 HermesAgent 为宿主的 FlowMind 运营产品
不是通用多智能体 playground
产品职责让运行态可见，让运营对象可管理，让治理闭环可执行
