实施链路主画布

用户真正看到的“和外界交互、内部执行、证据回写”都在这条链上。

输入源

CLI / Feishu / Webhook / Cron / API

多种平台入口把请求送到宿主运行面，是技术链路的上游信号。

Gateway / Session Runtime

Hermes 会话与消息面

生成 sessions、messages、tool_calls、token 数据，并维护 gateway_state 与连接状态。

Tool Dispatch

工具调度与执行

承接文件、终端、网络、MCP 与平台能力调用，形成动作和结果。

状态存储

state.db / gateway_state / jobs / memories

把会话、平台连接、定时任务、团队记忆和配置写成产品可消费的数据面。

协作与证据

.omx / handoff / harness traces

把运行态转换成协作工件、closeout 记录和仓库学习层，形成可追责证据。

产品消费面

Runtime / Operations / Governance / Collaboration

所有页面都不直接讲空话，而是消费这条链路的状态和工件来形成可操作视图。

技术约束与设计判断

这部分说明为什么我们把 TSX demo 直接接成 HTML 页面，而不是继续放空壳。

约束 1

当前仓库只保留了三个 TSX 入口文件，没有随同落库对应组件实现，因此不能继续把它们当作“已经实现”。

约束 2

WebUI 已经有稳定的 Flask 路由和静态资源体系，最短路径是把设计意图翻译成当前体系的正式页面。

判断 1

架构页必须接入真实数据和真实跳转，所以这里优先接 overview/runtime/handoff/skill/cron 等真实 API。

判断 2

不回到底层 API/表结构，不做字段级原型，而是把产品、结构、实施链路这三个视角直接落到可浏览页面。

证据流与工件流

技术架构最终是否成立，要看是否能回到真实工件。

Runtime
回到会话、工具、性能与异常的实时运行面。
Operations
回到技能、Cron、记忆和告警这些被运营的对象。
Collaboration
回到 handoff packet、runtime snapshot 与 closeout 证据。
Governance
回到 candidate / truth / review / drift 的治理工作面。
